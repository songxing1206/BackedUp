# 0.4.8：检索核查与调用保护

2026-10-13。首版无新增第三方依赖、无嵌入API、无向量模型下载。

- SQLite FTS5/BM25索引将相邻原文行组成最多8行／约1200字符的段落，保留原始行block ID；参考文献章节从候选检索排除。涉及明确数字、百分比、时间窗或统计量的主张会额外进行确定性数值候选排序（包括“52”与原文“52.19”这类小数报告值），再与 BM25 候选合并。数值相同只影响召回，不直接产生支持结论，指标、人群与时间范围仍由语义核查判断。
- 查询使用英文词、数字及可维护中英术语映射，移除括号中的作者年份；最多选8个首轮候选，再选8个新候选作为扩展，优先相关候选，剩余额度补相邻上下文。
- 预算按来源公平分配，不截断原文块。候选请求DATA目标上界约18 KB UTF-8，另含提示词。不是精确token计数，也不是准确率保证。
- 首轮判断、必要时扩展一次；首轮最多一次局部证据修复。默认不自动全文兜底、不复查改写建议；全文核查需要显式选择。
- 检索没证据不等于全文不支持；检索模式的“不支持”降为无法判断。正向／矛盾结论需原文证据和完整逐源矩阵，记录实际候选页码，报告标明非全文排除性核查。
- 每个请求发送前保存状态，收到响应后立即保存；响应可跨进程复用，失败／未知结果不自动重新收费。检查点存于data-v1/checkpoints，纳入备份。
- 每次调用前预留输入UTF-8字节上界＋256协议余量和输出上限，收到usage后释放差额；没有usage／不确定请求保留额度。默认每轮60请求、50万估算token，可在界面调整。HTTP和JSON适配器在优化管线不自动重发。
- 日志记录阶段、任务 ID、引用 ID、每条引用总处理秒数和实际 usage。普通核查默认处理全部引用；可在高级设置中用 Token 和请求上限控制消耗。人民币开支仍以服务商为准，重试开启新的预算。

原文真实性与 PDF 坐标是两个独立状态。逐字摘录已经在解析文本中核实、但字符框无法生成时，系统保留语义结论并标记“原文已验证但定位失败”，不生成猜测高亮。模型摘录不存在时则标记为无效证据并剔除；同一判断中的其他已验证证据继续保留。

## 离线探查

42篇任务的已匹配来源本地索引约6.11 MB，构建及27处查询约1.22秒，两轮候选JSON共574,147字节。这些字节不是token，不能与原账单直接计算省费比例。

旧模型保存的128个证据block中，检索候选覆盖73个。这不是人工金标，也不是语义召回率；仍有55个旧block未进入候选，显示关键词检索的局限。旧C001/C002的真实PDF探查能找到定义／流行率相关文字，但未重新调用模型验证结论。尚未实现通用跨语言向量检索，领域外中文术语可能漏检。

原始无正文统计：retrieval-probe-real.json、retrieval-probe-c001-c002.json。只有本地探查和假模型回归，不宣传固定省费比例或质量不下降。

扩展轮只为未判定来源选新候选，已验证的判断随上下文保留；无新材料的来源用空材料标识，不阻止其他来源核查。模型证据如果超出已提供候选／前轮证据，会降为无法判断。SQLite缓存同时绑定PDF解析版本。
