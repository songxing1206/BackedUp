# BackedUp V0.5 使用手册

## 最简使用流程

1. 启动 BackedUp，打开工作台。
2. 上传 `.md`/`.txt` 稿件，或直接粘贴正文。
3. 上传稿件引用的来源 PDF；支持一次多选。
4. 在“想检查什么”中选择：
   - **常规引用核查**：默认选项，优先使用 BM25 候选证据，调用较少。
   - **深度全文核查**：使用更大原文范围，运行更慢、调用更多。
5. 点击“开始检查”。

检查范围、引用格式、Token 预算和请求上限都放在“高级设置”中，普通使用无需修改。

上传 PDF 后会先在本地生成统一结构化文档。展开来源卡片并点击“查看文档解析结果”，可以核对标题、作者、年份、DOI、章节、页数、解析质量和 Markdown 预览。没有识别到作者时会额外显示首页转换文本。解析失败只表示文档转换需要人工检查，不会直接被判作文献身份错误。

## 默认模型

- 接入方式：自定义 OpenAI 兼容 API。
- 模型：`deepseek-chat`。
- Base URL：`https://models.sjtu.edu.cn/api/v1`。
- API Key 保存于本机私有数据目录，不写入源码、任务报告或执行轨迹。

如 Key 失效，点击工作台顶部“模型连接”更新即可。连接测试可能产生少量模型费用，但不会发送论文。

## 查看结果

完成后工作台会显示：

- 每处引用的支持结论和问题类型。
- 使用的原文证据与证据 ID。
- PDF 原文高亮和定位状态。
- 来源确认、候选检索、原文验证、PDF 定位、语义结论和人工复核分别显示；“定位失败”不再等同于“原文不存在”。

结果使用四色展示，但不会改写内部语义标签：绿色表示有已验证原文支撑的“支持”；黄色只表示“部分支持”；红色表示有已验证原文依据的“不支持/存在矛盾”，或有可靠书目依据确认的作者—年份错误；灰色表示来源、模型或证据链尚未可靠完成。PDF 高亮不可用只影响定位入口，原文已验证时不会把绿、黄、红自动改灰。每条详情的“查看判定依据”会同时列出 Agent 原始结论、程序保存结论、最终展示色和发生作用的程序规则。

年份字符串不同不会自动判错。系统分别记录 Online First 年份、正式出版年份、自动 PDF 元数据和人工/书目库确认依据；存在引用规范或年份后缀歧义时保持灰色。只有来源带有已确认的适用年份与依据时，才显示红色“引用年份错误”。
- 需要人工复核的项目。
- 请求次数、Token 和运行耗时。
- 任务质量摘要。

## 历史记录

- 普通核查：工作台左侧“历史记录”。
- A/B 和上下文消融：`架构与实验 → 实验历史`。
- 实验完成后可再次查看结果、真实执行轨迹，并导出 JSON/HTML。
- 删除普通历史记录不会自动删除其他数据版本中的记录。

## 运行实验

1. 先完成至少一个普通核查任务。
2. 打开“架构与实验”。
3. 点击“运行实验”。
4. 选择核查任务和实验目的：快速架构对比、三种上下文对比或完整对比。
5. 阅读预计分支、样本数和请求上限。
6. 明确确认可能产生付费调用后启动。

没有人工金标时仍可查看完成率、技术失败、Token、请求数、耗时和轨迹，但不能计算语义 Accuracy、Macro-F1 或 Recall@K。

## 高级设置

仅在下列情况使用：

- 设置本轮 Token 或请求上限；普通核查默认检查全部引用。
- 限制本轮请求或 Token。
- 使用 BibTeX 或 Zotero。
- 切换深度核查。
- 修改模型、Base URL 或 API Key。
- 为实验调整样本范围和预算。

## 常见问题

**提示未连接模型**：打开“模型连接”，确认 Key 仍有效并保存。

**找不到引用**：确认正文使用作者—年份格式，并且参考文献部分没有被当作正文。

**来源无法匹配**：检查 PDF 书目信息，可在来源卡片中人工确认作者和年份。

**没有准确率**：正式准确率必须导入人工金标；系统不会用合成数据冒充实际成绩。

**任务中断**：已经完成的结果会保留，从历史记录打开任务或使用重试功能继续。
