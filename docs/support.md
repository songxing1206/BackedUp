# 故障排查与反馈

| 现象 | 建议 |
| --- | --- |
| 本地地址拒绝连接／Failed to fetch | 确认应用已启动，使用实际端口；打开模型弹窗仍应可操作，但API测试需要本地服务就绪 |
| 系统拦截应用 | 核对来源、版本与SHA256，按系统安全提示处理；不要全局关闭系统保护 |
| 认证失败／403 | 核对所选供应商Key及账户权限；不要尝试把另一供应商Key填入 |
| 超时／限流 | 查看具体提示，等待或检查供应商网络、额度；避免连续重复测试增加费用 |
| 服务重启后不能检查 | 默认会话Key已失效，需要重新配置；已保存历史应仍存在 |
| 来源缺失／歧义 | 打开参考文献PDF核对作者、年份等信息，补充或指定来源，只补查对应项 |
| 原文验证失败 | 模型摘录未在 PDF 解析文本中出现；该摘录会被标为无效并剔除，不能支撑结论 |
| 原文已验证但 PDF 定位失败 | 保留已验证原文和语义结论，不生成猜测高亮；可打开 PDF 人工查看 |
| PDF 缺失 | 当前引用没有相关候选文件；使用“上传缺失 PDF”入口 |
| PDF 已上传但未匹配 | 核对已上传文件的作者、标题和年份后重新匹配 |
| 多候选或身份冲突 | 使用“选择候选来源”或“核对身份信息”，不要重复上传同一 PDF |
| Online First 与正式年份不同 | 保持灰色待确认；按投稿期刊采用的引用规范选择年份 |
| 红色“引用年份错误” | 仅在来源保存了可靠书目依据和已确认适用年份时出现；可在“查看判定依据”核对 |
| 超过材料限制 | 按提示减少PDF、拆分稿件或来源，不把截断结果视为完整判断 |
| 备份失败 | 先退出检查，检查外部或缺失附件；不要覆盖现有备份和恢复目录 |

反馈中只提交：产品版本、操作系统与架构、出错步骤、预期与实际行为、错误文案、供应商／模型ID、可选的虚构最小复现材料。诊断.command或诊断.bat仅输出版本、依赖与本地服务状态，不调用模型；先检查内容再分享。

不要提交API Key、settings/model.json、完整用户数据目录、真实论文、原始任务／检查JSON或未脱敏日志。截图可能包含论文正文、作者信息或个人路径，分享前需遮盖。若API Key已泄露，应到供应商处撤销并重新创建。

当前没有已配置的公开反馈网站或邮箱；仓库公开后可使用Issue模板。不要把个人数据上传到公共Issue。维护者可用虚构PDF和模拟API复现程序问题；学术结论需要作者复核。
